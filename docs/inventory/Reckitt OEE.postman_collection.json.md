## Auth flow
- Token requests (folder `techuser` #199-#202, plus root `Get Token` #203) POST to the IAM `/oauth/token` endpoint with `grant_type=client_credentials`. #199-#202 also send `tenant={{TENANT}}` and `iam-action=client_credentials.tenant-impersonation`.
- Each token request has a test script that stores the response into `TOKEN` (#203 also into a collection variable). All other requests then use Bearer `{{TOKEN}}`.
- Basic credentials: #199 uses `{{TU_DATA_INGEST_USERNAME}}`/`{{TU_DATA_INGEST_PASSWORD}}`, #201 uses `{{TU_OEEHBUB_OPERATOR_USER_*}}`, #202 uses `{{TU_OEEHBUB_USER_USER_*}}` (variables, values not in the file). #200 and #203 have inline credentials, see Findings.
- Other variables set by test scripts: `eTag`, plus about 80 created-resource IDs (`ASSET_ID`, `STATUS_ID`, `PRODUCT_ID`, `EXPRESSION_ID` and similar). These are chained from list/create responses.

## Findings
- Inline credentials (Basic username and password typed directly into the request, not variables):
  - Item `techuser / create TU OEEHUB Admin User` (#200), `request.auth.basic`
  - Item `Get Token` (#203, last item in the root), `request.auth.basic`
  - Not copied anywhere. See [auth-checklist.md](../auth-checklist.md).
- Hosts differ between token requests: #199, #201, #202 use `{{PIAM}}` (blank); #200 uses a hardcoded IAM host for the `greggs` tenant; #203 uses a hardcoded IAM host for the `reckitt` tenant. API calls use `{{HOST}}`. Which tenant the real calls target must be confirmed (`TENANT` default is `greggs`).
- `health / version` (#2) has `noauth` and a disabled `If-Match` header; `health / health` (#1) uses Bearer.
- Folder `MISC` (#193-#196) calls the Asset Management API (`{{HOST}}/api/assetmanagement/v3/assets...`), not the OEE API. It looks up asset IDs by name (`Machine0101`-`Machine0103`) and stores them in `ASSET_ID`.
