# Reference tables (VFC flows)

| At a glance | |
|---|---|
| **What this is** | Five small tables that describe assets, reasons, products, shifts and KPI targets. The dashboard joins them to `fact_kpi` and `fact_loss` |
| **How they are built** | One VFC tab for all five tables: `flows/vfc-reference-tables.json`. Shared settings come from the Config tab `flows/vfc-config.json`. Both are generated by `scripts/build-vfc-reference-flows.js` from `scripts/vfc/c*.js` and `r*.js` |
| **Status** | Imported and dry-run in the VFC by the user (2026-10-04), after the `glob` fix. File content not yet checked |
| **Output** | `<root>/<table>/<table>.parquet`, one file per table, replaced on every run. `dryRun` is true by default, set per table |
| **Trigger** | Weekly (Monday 07:00 UTC) and a `Run now` button. The data changes rarely |

## Settings: one place
- **Shared settings** live in node `1.1 CONFIG` on the Config tab: root folder, credentials, `sites` (name, `dayStartHour`, `assetIds`), exclusions, `calendarWindowDays`. The node stores them in **global** context (`glob.get('cfg')`: the VFC calls the global context `glob`, not `global`). It runs on deploy and when you click `Apply`.
- **Per flow** settings live in node `1.1 TASK SETTINGS` of the Reference tab: the dry-run switch per table. It copies the shared settings into flow context on every run, so a change in Config is used by the next run.
- **Secrets** are typed once, in the CONFIG node, after import. Committed files only have placeholders.
- Run the Config tab first (it also runs on deploy). Without it, TASK SETTINGS stops with `CONFIG not run`.

## Flow layout (one tab)
| Stage | What it does |
|---|---|
| 1 | Triggers, `1.1 TASK SETTINGS`, `1.2 Build run message` |
| 2 SETUP | Token, OEE asset list, choose assets, one message per asset |
| 3 ASSET | Per asset, three calls: Asset Management (hierarchy), OEE config (calendar and product collection ids), OEE thresholds. An excluded or unconfigured asset skips the OEE calls |
| 4 BUNDLES & ROUTE | One bundle per asset, join, then one message per table |
| 5 dim_asset, 6 ref_target_seed | Collect, decide, write |
| 7 to 12 | For `dim_reason`, `dim_product`, `dim_shift`: pick the distinct ids, read the master list for names, one call per id, join, collect, decide, write |
| 13 ERRORS, LOG, LOG WRITE | Catch, debug and CSV log, see [logging.md](logging.md) |

The config call of an asset is made once and feeds `dim_asset`, `dim_product` and `dim_shift`. The reason tree id comes with the asset list.

## The tables
| Table | One row is | API calls (all GET) | Columns |
|---|---|---|---|
| `dim_asset` | one OEE asset | OEE asset list, Asset Management `/assets/{id}` (hierarchyPath), OEE `/assets/{id}/config` | `asset_id`, `asset_name`, `site`, `area`, `line`, `machine`, `is_manual`, `is_configured`, `calendar_id`, `product_collection_id`, `reason_tree_id`, `loaded_at` |
| `ref_target_seed` | one asset and one KPI | OEE `/assets/{id}` (thresholds) | `asset_id`, `asset_name`, `kpi`, `warning`, `error`, `is_set`, `loaded_at` |
| `dim_reason` | one reason in one tree | `/reasontrees`, `/reasontrees/{id}/reasons` | `reason_tree_id`, `tree_name`, `reason_id`, `reason_name`, `parent_id`, `level`, `top_level_name`, `full_path`, `justification`, `loaded_at` |
| `dim_product` | one product in one collection | `/productCollections`, `/productCollections/{id}/products` | `collection_id`, `collection_name`, `product_id`, `code`, `name`, `description`, `design_speed_value`, `design_speed_unit`, `design_speed_interval`, `design_speed_type`, `design_speed_per_hour`, `loaded_at` |
| `dim_shift` | one calendar event (shift definition) | `/calendars`, `/calendars/{id}/calendarEvents?from&to` | `calendar_id`, `calendar_name`, `time_zone_text`, `event_id`, `shift_name`, `description`, `time_model_category_id`, `duration_ms`, `freq`, `interval`, `start_utc`, `until_utc`, `loaded_at` |

Types: text = UTF8, `is_*` and `justification` = BOOLEAN, `level`, `duration_ms`, `interval` = INT64, `warning`, `error`, `design_speed_*` numbers = DOUBLE, `loaded_at`, `start_utc`, `until_utc` = TIMESTAMP_MILLIS.

## Rules built into the flow
- **Distinct ids are called once.** 38 assets share about 10 reason trees, so each tree, collection and calendar is read once, not once per asset. The master lists give the names.
- **No half tables.** If any call that a table needs fails, that table is not written and the log says `FAILED, NOTHING WRITTEN`. The other tables are not affected.
- **Test Line is excluded in every table** (`excludeAncestorNames` in Config), because the hierarchy is read once per asset. The first version only did this for `dim_asset`.
- **Same keys as `fact_kpi`.** `site`, `area`, `line` and `machine` come from the hierarchy path with the same rule, so the tables join on `asset_id`.
- **`dim_asset` keeps unconfigured assets** (`is_configured` false, ids empty). The other four tables skip them.
- **`design_speed_per_hour`** is the only derived speed: SECOND x 3600, MINUTE x 60, HOUR x 1. Any other interval gives null, so a new interval is visible and not guessed.
- **`full_path`** joins the names with ` / `, the same format as `reasonFullPath` in `downtimeReasons`.
- **`is_set`** is true when the warning or the error value is above 0. A KPI that the response does not list gives null values and `is_set` false.

## Checked on the mock, not yet on the real tenant
- **Calendar events.** The shape comes from `config-and-master-data.md`: `rrule` as an object with `freq`, `interval`, `dtstart`, `until`. If the real answer has `rrule` as text, `freq`, `interval`, `start_utc` and `until_utc` stay empty (no guessing). The `from` and `to` window (`calendarWindowDays`, 31 days) decides which events come back.
- **Config of unconfigured assets.** Not called any more (the asset is flagged `is_configured` false in the asset list), so the open question about its answer is gone.
- **Global context** in the VFC function nodes is called `glob`, not `global` (found by the user on import; the generated code uses `glob`).
- **Not in these tables:** `productionTarget` (a time series, not a target value), loss and category targets, CU factor, SKU master (not in the API, see `prompt-response/report-data-coverage.md`).
