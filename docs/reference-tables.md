# Reference tables (VFC flows)

| At a glance | |
|---|---|
| **What this is** | Five small tables that describe assets, reasons, products, shifts and KPI targets. The dashboard joins them to `fact_kpi` and `fact_loss` |
| **How they are built** | One VFC flow per table: `flows/vfc-ref-<table>.json`, generated by `scripts/build-vfc-reference-flows.js` from `scripts/vfc/r*.js` |
| **Status** | Built and tested on the mock Insights Hub only (2026-10-04). Not yet run against the real tenant or in the VFC editor |
| **Output** | One parquet file per table with a fixed name (`mufti_test/<table>/<table>.parquet`), replaced on every run. `dryRun` is true by default |
| **Trigger** | Weekly (Monday 07:00 UTC) and a `Run now` button. The data changes rarely |

## The tables
| Table | One row is | API calls (all GET) | Columns |
|---|---|---|---|
| `dim_asset` | one OEE asset | OEE asset list, Asset Management `/assets/{id}` (hierarchyPath), OEE `/assets/{id}/config` | `asset_id`, `asset_name`, `site`, `area`, `line`, `machine`, `is_manual`, `is_configured`, `calendar_id`, `product_collection_id`, `reason_tree_id`, `loaded_at` |
| `ref_target_seed` | one asset and one KPI | OEE `/assets/{id}` (thresholds) | `asset_id`, `asset_name`, `kpi`, `warning`, `error`, `is_set`, `loaded_at` |
| `dim_reason` | one reason in one tree | `/reasontrees`, `/reasontrees/{id}/reasons` | `reason_tree_id`, `tree_name`, `reason_id`, `reason_name`, `parent_id`, `level`, `top_level_name`, `full_path`, `justification`, `loaded_at` |
| `dim_product` | one product in one collection | `/assets/{id}/config`, `/productCollections`, `/productCollections/{id}/products` | `collection_id`, `collection_name`, `product_id`, `code`, `name`, `description`, `design_speed_value`, `design_speed_unit`, `design_speed_interval`, `design_speed_type`, `design_speed_per_hour`, `loaded_at` |
| `dim_shift` | one calendar event (shift definition) | `/assets/{id}/config`, `/calendars`, `/calendars/{id}/calendarEvents?from&to` | `calendar_id`, `calendar_name`, `time_zone_text`, `event_id`, `shift_name`, `description`, `time_model_category_id`, `duration_ms`, `freq`, `interval`, `start_utc`, `until_utc`, `loaded_at` |

Types: text = UTF8, `is_*` and `justification` = BOOLEAN, `level`, `duration_ms`, `interval` = INT64, `warning`, `error`, `design_speed_*` numbers = DOUBLE, `loaded_at`, `start_utc`, `until_utc` = TIMESTAMP_MILLIS.

## Rules built into the flows
- **Distinct ids are called once.** 38 assets share about 10 reason trees, so each tree, collection and calendar is read once, not once per asset. The master lists give the names.
- **No half tables.** If any call fails, nothing is written and the log says `FAILED, NOTHING WRITTEN`, as in the fact flow.
- **Same keys as `fact_kpi`.** `site`, `area`, `line` and `machine` come from the hierarchy path with the same rule, so the tables join on `asset_id`.
- **`dim_asset` keeps unconfigured assets** (`is_configured` false, ids empty). The other four tables skip them.
- **`design_speed_per_hour`** is the only derived speed: SECOND x 3600, MINUTE x 60, HOUR x 1. Any other interval gives null, so a new interval is visible and not guessed.
- **`full_path`** joins the names with ` / `, the same format as `reasonFullPath` in `downtimeReasons`.
- **`is_set`** is true when the warning or the error value is above 0. A KPI that the response does not list gives null values and `is_set` false.

## What is not verified (the live check was skipped)
- **Calendar events.** The shape comes from `config-and-master-data.md`: `rrule` as an object with `freq`, `interval`, `dtstart`, `until`. If the real answer has `rrule` as text, `freq`, `interval`, `start_utc` and `until_utc` stay empty (no guessing). The `from` and `to` window (`calendarWindowDays`, 31 days) decides which events come back.
- **Config of unconfigured assets.** Assumed to answer with an error status. `dim_asset` treats any non-200 config of an unconfigured asset as "no ids".
- **Test Line.** `excludeAncestorNames` is applied only in `dim_asset` (it needs the hierarchy). The other four flows would include a test asset if the asset list is empty (all assets). The default list in CONFIG avoids this.
- **Not in these tables:** `productionTarget` (a time series, not a target value), loss and category targets, CU factor, SKU master (not in the API, see `prompt-response/report-data-coverage.md`).
